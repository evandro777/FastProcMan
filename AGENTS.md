# AGENTS.md: FastProcMan

Notes for AI agents and contributors. Read this before changing anything.

## What this is

A **light and fast** Linux process manager in Rust + Slint: sort/filter processes by CPU and memory, flag suspicious ones, end or kill one quickly, and graph CPU (and each core), memory (and swap), network, GPU and each disk. Priorities: fast start, low memory and CPU, simplicity. Measured on a real desktop (490 processes, 2 s refresh): ~24 MB RSS, ~1.2% of one core. The default refresh is now 1 s, which should be about twice the CPU: not re-measured yet. Re-measured with per-core/per-disk/GPU history (`--profile fast`, Graphs tab, 1 s, NVIDIA desktop, 60 s): 29.7 MB `VmRSS` (9.4 MB `RssAnon`), 2.7% of one core **without** NVML; 50.4 MB (25.9 MB `RssAnon`), 3.2% **with** it. So opening NVML costs about 21 MB of RSS and 0.4% CPU (it loads `libcuda` and others); the rest of the page is cheap.

## Layout notes

`crates/core` is UI-independent (no Slint) so a CLI can reuse it; `crates/app` is the Slint UI. `flatpak/build.sh` builds outside the repo (`~/.cache/fastprocman-flatpak`). `scripts/ui-snapshot.sh` renders pages on a private Xvfb with canned data (`crates/app/src/fixtures.rs`, env `FASTPROCMAN_FIXTURES=empty|single|many`, `FASTPROCMAN_PAGE=<n>|about|confirm|confirm-kill|properties|menu|settings|tree`) to `target/ui-snapshots/`. `dev/gen_po.py` writes the `.po` files from one table. Keep `README.md` (short, for users), `docs/FEATURES.md` (every behaviour in detail) and `BUILD.md` in step with behaviour. The screenshots in `docs/screenshots/` are made with the snapshot script on the `many` fixture and cropped to the 860x560 window: `main.png` (processes, with the amber banner) as is, `tree`, `services` and `graphs` with `FASTPROCMAN_CALM=1` (no banner), e.g. `FASTPROCMAN_CALM=1 MODES=many scripts/ui-snapshot.sh tree` then `convert target/ui-snapshots/tree-many.png -crop 860x560+0+0 +repage docs/screenshots/tree.png`. Redo them after a visible UI change.

System deps: `libfontconfig-dev libxkbcommon-dev libxkbcommon-x11-dev libx11-dev libxcb1-dev`. No GL/Skia/femtovg.

## Architecture decisions (inherited from FastMoji, measured there)

- **Software renderer only** (`winit` + `software`, forced in `main.rs` and in `Cargo.toml` features with `default-features = false`): ~27 MB RSS versus ~108 MB with the GL renderer.
- No async runtime. Scans/work in threads, results handed to the UI thread with `slint::invoke_from_event_loop`.
- Never hold a `RefCell` borrow while calling something that makes Slint re-read a model.
- Keep dependencies few and light.
- Slint notes: a `VerticalLayout` inside a `ScrollView` needs `alignment: start`, or a short list spreads its rows over the window; read-only `TextInput` (one per block) makes text selectable; use `content-y` (not `viewport-y`); a callback named `close` shadows a builtin (use `dismiss`); `FocusScope.capture-key-pressed` intercepts keys before `LineEdit`; a wrapped read-only `TextInput` in a nested layout reports one line of height, so give it room with `min-height`, estimated from the available width (a fixed character count leaves a blank band under lines that still fit on one line); `Text` and `TextInput` have no `padding`, so put the space in the parent layout's `spacing` or `padding`.

## Process manager notes (measured or checked in the Slint 1.18 sources)

- `/proc` is read directly (no `sysinfo`, no `libc`). Per process: `stat` (the name sits between the first `(` and the **last** `)`), `status` (real uid, `RssAnon` = `Proc::mem_kb`, GNOME's "Memory": private memory, so shared pages are not double-counted in tree and app totals; Properties also reads `VmRSS`, `RssFile` + `RssShmem` and `VmSize` on demand) and the `exe` link (EACCES for other users' processes: those never get a warning). CPU % = process tick delta / total tick delta (first 8 `cpu` fields, guest excluded) x cores, so 100 = one core. Previous ticks are keyed by `(pid, start)`, so a reused PID gets no bogus delta. `Sampler::new()` takes a priming reading; the sampler thread waits 300 ms before the first real one.
- Network and disk totals only count devices that have a `device` entry under `/sys/class/net/<if>` and `/sys/block/<name>`: that drops lo, veth, bridges, VPNs, loop, zram, dm-* and md* (all of which double-count).
- The table is re-sorted and rebuilt every tick, so a row index is never trusted: the selection is stored as `(pid, start)` and `kill` re-reads `start` right before signalling (`Exited` if it changed). Rust sets `selected-row` after replacing the model; Rust never calls `ProcessesPage.select-row` (it emits `row-selected` and scrolls). The Slint side does, on purpose, for user actions only (a click, a right click, Up/Down, PageUp/PageDown): it ignores out-of-range rows, so Up with nothing selected is a no-op. `selected-row` is not clamped when the row count shrinks, but Rust sets it on every refresh.
- `State` lives in a `thread_local` on the UI thread. Build the `View` while it is borrowed and apply it after, so no borrow is held across a Slint call. (`row-selected` fires only from `select-row`, never from `set_vec` or from Rust setting `selected-row`.)
- `kill` runs the commands with `LC_ALL=C`: it matches "not permitted" / "No such process" in stderr, which are translated otherwise (pt_BR would never reach pkexec). Process names and exe paths are read lossily (invalid UTF-8 must not hide a process or escape the warnings). The PID-reuse check happens before the polkit dialog, not after it.
- The table is our own (`HeaderCell` + a `ListView` of `ProcRowItem`, fixed 24 px rows, in `main.slint`), because `StandardTableView` cells are text only and cannot indent or hold an icon. Column widths are in the `Cols` global, shared by header and rows; the fluent `ListView` scroll bar is 14 px and drawn over the rows, so both keep `Cols.bar` of right padding. Do not name a property `row` or `color` on a `Rectangle` (built-ins). A row is a `ProcRow` struct filled in Rust.
- Sorting is done in Rust on the numbers (`compare` in `main.rs`), from the header's `sort-ascending/descending(column)` callbacks; the page keeps the arrow state (`sort-col`, `sort-asc`; text columns start ascending, the others descending).
- **Tree** (`settings.tree`, the "Tree" switch): `core::tree::build` turns `Proc.ppid` into the visible rows (pure, tested). Rows start expanded: a row is open when `State.open_by_default != State.flipped.contains((pid, start))`, so a clicked row is one exception, and the "Tree" switch and the "Expand all" / "Collapse all" buttons (all in `Main`'s bottom bar, only in tree mode on the Processes tab: the filter row has no room for them at the 640 px minimum width, where they pushed the settings button off the window) set the default and clear the exceptions, which makes programs that start later follow the last choice. None of this is saved; only `tree` is. A collapsed parent shows its subtree's CPU and memory, an open one its own; siblings are sorted by the subtree totals so opening a row never moves it. A filter shows the matches and their ancestors, forced open. The count in the status bar is of matching processes, not rows. A selection hidden inside a collapsed parent moves to the nearest shown ancestor (not when a filter hid it). The walk is a DFS from the roots with a seen set: a PID reused within one sample can make a parent cycle, and none of its members may vanish or loop.
- **Services tab** (`crates/core/src/services.rs`, `crates/app/src/svc.rs`): `systemctl list-units --all` (7 ms) every tick, **only while the tab is shown** (`Cmd::Services(bool)` from `Main.changed page`), parsed as plain text (`--plain --no-legend`; `not-found` units dropped); `list-unit-files` (**0.73 s**, so never per tick) once when the tab opens, in the sampler thread, for the Startup column and installed-but-unloaded units. PID/CPU/Memory come from `/sys/fs/cgroup/**/<unit>.service/cgroup.procs` (not `systemctl show`, 100 ms) summed over the same sample's `Proc`s; the walk stops at a `*.service` directory (`shortcut:` in the code: delegated services such as Docker under-count). Status = sub `running` / active-but-not-running (Exited) / failed / rest; the Stopped filter includes Exited. Two ComboBoxes (Status, Startup) combine with the name filter; typing on the tab goes to its filter (`svc::type_char`). `control()` runs `systemctl <verb> -- <unit>` and lets polkit prompt (no pkexec; "Access denied" = `Cancelled`, "Interactive authentication required" stays `Failed` so a missing polkit agent, the open Flatpak-host question, is not mistaken for a cancel). The selection is the unit name. polkit's `manage-units` is `auth_admin_keep`, so only the first action prompts for a few minutes: Stop and Restart therefore go through `Confirm` (`confirm-service` 1/2, `Main.confirm-accept` is the only caller of end/kill/stop-service/restart-service). Skipped: user services, enable/disable, a context menu, keyboard navigation and Description. Fixtures never start the sampler, so `systemctl` is never run for a snapshot.
- **App groups** (tree mode): `tree::build` takes `app(&Proc) -> Option<&str>` and cuts every process whose app differs from the one it sits in (own app, else its parent's) out of its parent, setting **`parent[i] = None`** too: the selection walk in `view()` follows `parent`, and collapsing Code must never move the selection onto Files. Group rows have key `(0, hash(name))` (`tree::group_key`; PID 0 is never real), `""` is "Processes" (always last, label from `Tr.group-processes`). Apps start closed (`apps_open_by_default`), Processes open; Expand/Collapse all set both. Group rows show their totals open or closed. A closed group, and a collapsed row, also show the worst **strong** warning inside what they hide (`tree::Row::hidden_warn`, carried up in the same backward pass as the sums, red like any strong flag), so a `/tmp` look-alike of Firefox is not lost behind a closed group; a collapsed row keeps its own warning when that one is strong. Sorting by Warning still uses the row's own warning. With no app known, or `settings.group_apps` off (Settings switch, default on; `State.group_apps` makes the `app` closure return `None`), there are no group rows. Space in Settings still flips only the CPU switch. `select()` finds no process for a group key, so `selected` is `None` and every process action is gated on `selected-label != ""`, not `selected-row >= 0` (menu, Delete, Alt+Enter, Menu key, right click). `s.apps` (icon key -> name) is filled with the icons. Manual check against another task manager: `cargo test -p fastprocman live_apps -- --ignored --nocapture`. Skipped: an "N apps" header, localized `Name[xx]`, ending a whole app. cgroups are not used: on Cinnamon native apps share `session-*.scope`.
- **Icons** (`crates/app/src/icons.rs`): the window opens with empty icon slots; the first sample's programs go to one resolver thread, which builds an index once (`.desktop` files by program, `StartupWMClass` and file name; theme `apps` folders by icon name) and sends back paths. The UI thread decodes them (`slint::Image` is not `Send`) and refreshes once per batch. Keys are the exe path, else the name (`icon_key`); a miss is never retried, and nothing is invalidated while the app runs. The same lookup gives the application name (`Index::app`), stricter than the icon: only launchers without `NoDisplay`/`Hidden`, a key claimed by two different `Name=`s gives none, and the theme/pixmaps fallbacks never name an app. The icon slot is 16 px, so small PNGs win over big ones and SVGs.
- **Slowdown banner** (`sys::pressure` -> `Alert`, `SysStats.psi_*`, `Main.alert-*`): `/proc/pressure/{cpu some, memory some, io full}` `avg10`, read every sample (3 tiny files; 0 when missing); thresholds are consts in `sys.rs`. Memory is also judged on available memory: **watch** (amber, "opening another big app may freeze") under `MEM_WATCH_PCT` 20%, **danger** (red) under `MEM_DANGER_PCT` 10% (earlyoom's point) or `memory some` over 10%. Measured on the owner's 32 GB / 256 MB-swap machine: a fast allocation went from fine to OOM-killed with only ~3 s of memory stall in total, and at 10% left the desktop was already unresponsive, so the stall figures alone, and even 10%, warn too late (`memory full` needs every task blocked at once, so it was dropped for `some`). Worst wins: memory, then disk, then CPU. Up to three culprits (`MAX_CULPRITS`): biggest `mem_kb`, `D`-state processes (none is fine: no buttons), busiest `cpu_pct` of at least `CPU_CULPRIT_MIN`. The banner sits above the `TabWidget` (every tab, not in `status`, which action results overwrite); its button row is built only with `alert-items.length > 0` (an empty layout stretched the banner to 190 px). `State.alert` holds the culprits in button order, and `ProcRow.risky` draws their rows amber. A click (`on_alert_clicked`) clears the filter and "Suspicious only", expands the whole tree (like Expand all: the culprit may sit in a closed app group or collapsed parent, where no row can be selected), selects the culprit, switches to page 0 and calls `reveal` (the scroll half of `select-row`; Rust sets `selected-row` but cannot scroll); it never ends anything, Delete → Confirm still does. Snapshot fixtures: `many` ~85% used (amber, three buttons), `single` red disk with no buttons. Not checked: 640 px width in pt_BR (the message wraps), many culprit buttons with long names, and a live run of the new thresholds.
- **Graphs page**: Rust builds every card (`State::graph_cards`: CPU, Memory, Network, each GPU, each disk) as a `GraphData` (`title`, `value`, `extra` second line, `legend` + `paths` by position, `faint` = every core as sub-paths of one string), so titles and legend names are `Tr` functions. `State.graphs` is one `VecModel` updated with `set_row_data` while the card count is unchanged (keeps the scroll position). The cards are built only while the tab is shown (`view(tr, graphs)`, `ui.get_page() == 1`); the history is recorded either way, and `Main.page-changed` calls `refresh` so opening the tab does not wait for the next tick. `GraphsPage` is a `ScrollView` of rows of two cards; an odd last card gets a placeholder so it keeps half width. Slint gotchas found here: `if cond: for ...` is a syntax error (use `visible`), and an **empty `GridLayout` caps its card's width at the minimum**, so the legend grid is built only when `legend.length > 0`. `Hist` keeps one series per core, per disk (matched by name, dropped when the disk vanishes) and per GPU. A disk or network adapter seen for the first time shows 0, not its lifetime total (both keep a per-name previous reading). Snapshot page `graphs-tall` is the same page in a 860x1150 window (the default window hides the lower cards); the `single` fixture has no swap, GPU or second disk, `many` has three disks so the card count is odd.
- **GPU** (`crates/core/src/gpu.rs`): NVIDIA through NVML, `dlopen`ed at run time (`libnvidia-ml.so.1`, glibc 2.34+ has `dlopen` in libc; no crate, no link-time dependency; the one `unsafe` block). Opened after the sampler's priming reading. AMD through `/sys/class/drm/card<N>/device/{gpu_busy_percent,mem_info_vram_*}` (no encode/decode). Intel: not supported. While every NVIDIA card's `power/runtime_status` is `suspended` the last memory figures are returned with 0 load, so a sleeping laptop dGPU is not woken every second (untested on real hardware). A suspended AMD card is not read either, but it is kept in the list (`read_amd(drm, last)`): load 0 and the memory figures of the previous reading, so the card does not come and go on the Graphs page and the position-matched history of the other cards does not shift. Unlike NVIDIA, a card that is already asleep at start is listed with memory 0 (untested on real hardware). Cost: about +21 MB RSS (see the top of this file); an option if that matters is to open NVML only the first time the Graphs tab is shown. `cargo test -p fastprocman-core live_nvml -- --ignored --nocapture` prints a reading to compare with `nvidia-smi`. In the Flatpak host relaunch `--library-path` points at the runtime, so the host's `libnvidia-ml` is probably not found there and the GPU card is simply absent: untested.
- The three pages are stacked in one `Rectangle` under our own `TabItem` bar (not Fluent's `TabWidget`, which stretches the tabs over the whole width) and only hidden with `visible: root.page == n`. Pages made with `if` would be destroyed on every tab switch and lose the scroll position and sort arrows. Ctrl+Tab is in `Main.shortcuts`.
- **Look** (cosmetic pass): the accent is the desktop's, not ours (Fluent's `accentify()` takes `SlintInternal.accent-color`), so use `Palette.accent-background`, never a hard-coded green. A selected row is a 22% accent tint plus a 3 px bar on the left, with its own text colour kept: the old solid `selection-background` with black text hid the amber and red flags. Every other row has a 3% shade (`odd`). Headers are weight 500 at 70% alpha, the sorted one at full strength with an accent arrow. Graph cards draw quarter lines, a soft area under the first series (`GraphData.fill`, from `area()` in Rust) and the legend packed left when it has one or two names. The slowdown banner has a 4 px stripe, not a border. Fonts are the system's on purpose (no bundled face: size and memory, and it should look like the rest of Cinnamon); Slint 1.18 has no `font-features`.
- Sparklines are `Path`s with `fit: fill` (the default `contain` keeps the viewbox aspect and draws a small centred line). Rust writes the points in a 59 x 100 box, newest sample at the right, y = 100 - v. Strokes are not scaled by `fill`.
- A child of a plain `Rectangle` keeps its preferred size: give the table's `VerticalLayout` and overlay `Text` `width/height: parent`.
- `kill` blocks on pkexec (the polkit dialog), so it always runs in its own thread. Order: `/usr/bin/kill`, then `pkexec /usr/bin/kill` only if stderr says "not permitted"; pkexec exit 126/127 is "cancelled".
- The `/tmp/.mount_*` AppImage exemption holds only when that folder is a mount on another device than `/tmp` (`is_appimage_mount`): a plain folder with that name is flagged. Not verified against a real AppImage yet.
- The Warning rules and their known noise are documented on `suspicious` in `sys.rs`. `NameMismatch` fires on Firefox/Electron children and on `claude`; it is shown but not part of the "Suspicious only" filter (`Reason::is_strong`).

### Real test of the pressure warning

Run the Fast build (`target/fast/fastprocman`) and, in a terminal, this ramp: it adds 512 MB every 5 s (touched, so it is really resident) and `Ctrl+C` frees it all at once. Expect the amber banner naming `python3` when under 20% of the memory is available (about 6.4 GB left on 32 GB, while the desktop still responds) and red under 10% (it did not trigger with `stress-ng --vm`, which stayed at ~2 GB). Click the `python3` button, then `Delete` and confirm. If earlyoom is off the kernel's OOM killer ends the ramp at the end, after a possible freeze: stop it first. `stress-ng` alone is not a good test here (it never grew past ~2 GB); to see the stall figures without risking the machine use `systemd-run --user --scope -p MemoryHigh=1G -p MemoryMax=2G stress-ng --vm 1 --vm-bytes 3G --vm-keep`.

```sh
python3 -c "
import time
b = []
while True:
    b.append(bytearray(b'x') * (512 * 2**20))
    print(len(b) * 512, 'MB', flush=True)
    time.sleep(5)
"
```

CPU: the stall figure (`cpu some` over 60%) needs more busy loops than cores. This starts twice as many for 60 s (`Ctrl+C` stops the wait, the loops end by themselves); the red "CPU overloaded" banner needs 10 to 20 s, because the figure is a 10 s average. Each loop gets about 50% of a core, right at `CPU_CULPRIT_MIN`, so the buttons may be empty or flicker (not checked on the real machine).

```sh
for i in $(seq $(( $(nproc) * 2 ))); do (nice -n 10 sh -c 'while :; do :; done') & done; sleep 60; kill $(jobs -p)
```

## GitHub flow and releases

Work on branches, PRs to `master`. CI: `ci.yml` (fmt, clippy, tests, MSRV, metainfo/desktop validation), `appimage.yml` (AppImage on every push/PR; on a `v*` tag it attaches to the release), `flatpak.yml` (bundle on every push/PR; on a `v*` tag it also publishes the signed remote and the landing page to GitHub Pages, then attaches the bundle), `virustotal.yml` (scans the AppImage and the Flatpak after their workflows; needs the `VIRUSTOTAL_API_KEY` secret). `RELEASING.md` has the one-time setup and the steps. Never commit or push on the owner's behalf.

Release gotchas (each one broke a first release):

- Bump the version in `Cargo.toml`, then run `cargo check` and commit `Cargo.lock`: CI uses `--locked`, so a stale lock fails every job.
- The metainfo needs a `<release version="X">` for the tag, or `flatpak.yml` fails.
- `appimagetool` builds `.DirIcon` from a PNG at the AppDir root, not from the SVG. Regenerate `packaging/io.github.evandro777.FastProcMan.png` when the SVG changes: `convert -background none -density 384 packaging/io.github.evandro777.FastProcMan.svg -resize 256x256 packaging/io.github.evandro777.FastProcMan.png`. ImageMagick ignores gradients and opacity in the SVG, so use solid colours.
- The first tag needs the one-time setup in `RELEASING.md`: the signing key and its secret, Pages, and the `v*` tag rule on the `github-pages` environment.

## Flatpak

App id `io.github.evandro777.FastProcMan`; `flatpak/build.sh --devel` installs `...FastProcMan.Devel` next to a release. Needs `flatpak-builder` and `org.freedesktop.Sdk//25.08` + `org.freedesktop.Sdk.Extension.rust-stable//25.08`. The runtime version `25.08` appears in five places (the manifest, the container image tag, the rust-stable install and its `GITHUB_PATH` line in `flatpak.yml`, and the header of `flatpak/build.sh`): bump them together.

- Auto-update = our own signed OSTree remote on GitHub Pages (`flatpak.yml`: `bundle` → `pages` → `release`), deployed on `v*` tags only. Every deploy replaces the whole site, so never deploy Pages from another trigger. The public key is `flatpak/signing-key.b64` (base64 of the binary export, made by `flatpak/new-signing-key.sh`; the template ships none); the private half is the secret `FLATPAK_GPG_PRIVATE_KEY`. See `docs/FLATPAK-SIGNING.md`.
- Keep `finish-args` minimal (the manifest says how for X11-only apps and trays). The build vendors crates (`cargo vendor`), so `flatpak/vendor` must not be in the manifest's `skip:`. Keep build dirs out of Dropbox-synced folders.
- Patterns to copy when an app needs them (FastPaste has each one working): inside the sandbox `FLATPAK_ID` is set. A single-instance Unix socket must live in `$XDG_RUNTIME_DIR/app/$FLATPAK_ID/`, the only directory shared between `flatpak run`s. A ksni tray needs `.disable_dbus_name(true)` there. Start at login must go through the Background portal (`org.freedesktop.portal.Background.RequestBackground`, blocking, so from a thread), not a file in `~/.config`. A host command (for example `tesseract`) is reachable only through `flatpak-spawn --host`, which needs `--talk-name=org.freedesktop.Flatpak`. Normally that is the user's own opt-in `flatpak override`, never in the manifest. **FastProcMan is the exception**: the owner wants a Flatpak that sees every process (like Mission Center), so our manifest has it, `src/host.rs` relaunches the app on the host, and the README warns that it is not sandboxed. Do not copy that to a Flathub manifest.
- `src/host.rs` runs `flatpak-spawn --host --watch-bus` with the runtime's `ld.so` and `--library-path` (`<runtime>/lib/<triple>:<app>/lib`, both host paths read from `/.flatpak-info`), `FASTPROCMAN_ON_HOST=1` and `XDG_DATA_HOME` forwarded, display variables not. A copy that exits non-zero in under 30 s counts as failed and the app carries on in the sandbox with a status message. It only relaunches when `FLATPAK_ID` starts with the app id, so another Flatpak's variable cannot trigger it.
- **Flathub policy:** manifests must NOT contain AI-generated content and AI must not open the submission PR. Do not write a Flathub manifest or submission text for the owner; `docs/FLATHUB.md` explains the process.

## Open items

- **Flatpak on the host is untested on a real desktop** (see the Flatpak section). Biggest unknown: pkexec from a process started by the user's systemd, outside the login session, may say "Not authorized" without a prompt. Also unknown: fonts and xkb data come from the host.
- Not built: column resizing, per-process network (needs root or eBPF) and per-process disk columns (Properties shows read/write totals instead), tray, clearing the status line after a while. The Up/Down shortcuts from the filter go through `select-row` and leave the keyboard focus in the filter.
- Numbers use `.` as the decimal separator in every language (formatted in Rust).
- CPU is ~1.2% of a core at 2 s with ~490 processes. A cheap win if it matters: `statm` instead of `status` for RSS (needs the page size without `libc`). Do **not** cache the uid or the warning per `(pid, start)`: a process can `exec /tmp/evil` and keep both, and a cached "clean" verdict would hide it (setuid changes the uid the same way).
- Tests that spawn a child take the `SPAWN` lock in `sys.rs`: a child forked while another test still has a freshly copied binary open for writing makes its exec fail with `ETXTBSY`.
- Driving the real app on a private Xvfb: `xdotool key` needs XTEST (no `--window`; winit ignores synthetic key events) after `xdotool windowfocus`. Clicks are relative to the window.
