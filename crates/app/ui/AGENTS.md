# UI notes (dialogs, menu, shortcuts, focus)

Read this before changing `main.slint` or the handlers in `crates/app/src/main.rs`. The root `AGENTS.md` has the project-wide rules, including how to verify UI changes.

- Dialogs (`About`, `Confirm`, `Properties`) are in-window overlays (the last children of `Main`), not second windows: closing Main always ends the app and `scripts/ui-snapshot.sh` can capture them (`FASTPROCMAN_PAGE=about|confirm|confirm-kill|properties`). About's version comes from `CARGO_PKG_VERSION`, the Website button opens `CARGO_PKG_REPOSITORY` with `xdg-open`.
- `Confirm` guards End and Kill (menu, `Delete`, `Shift+Delete`, and the bottom bar's End… button, shown only with the tree off: with Expand/Collapse the bar overflows 640 px in pt_BR) and, on the Services tab, Stop and Restart: `ProcessesPage` only emits `end()`/`kill()`, `Main.ask()` / `Main.ask-service()` open the dialog (copying the label, because the sampler keeps rewriting `selected-label`; `confirm-service` is 0 for a process, 1 stop, 2 restart), and only `Main.confirm-accept()` (its `accepted` and Enter) calls the Rust `end`/`kill`/`stop-service`/`restart-service` callbacks. Never open it from Rust (except the snapshot page), and never call those callbacks from anywhere else. The title shows the process's icon (`Main.confirm-icon`, copied from the selected row in `ask()` like the label; empty when it has none, never for a service). The filter box (the kit's `SearchBox`, whose `key(event)` callback runs before its text field; `return accept` stops the key there), which has the focus from the start, used to eat Delete (it erases the next character) even after the arrow keys had picked a process: its `key` handler now asks to end (Shift: force quit) when `in-list` (selection last moved by the arrows from the box, reset by editing, Ctrl+F, Escape) or the box is empty; the box does not expose its cursor, so with typed text and no arrow use Delete still erases. `act_selected` also refuses End and Kill (status "Exited", nothing sent) when `confirm-label` no longer equals the live selection's label: in tree mode the selection moves to a shown ancestor when its row gets hidden, and the dialog must never signal a process it did not name. The same check guards Suspend, Resume and Priority against `menu-label`, the selection's label copied when the context menu opens (`ProcessesPage.menu-label`, set before both `menu.show` calls). Start does not ask. The Services tab keeps its own filter (`svc-filter`): Escape and Ctrl+F in `Main.shortcuts` are routed by `page`; Up/Down, Page keys and Delete stay Processes-only; typing works on both (`type_char` in `main.rs` routes by `page` to `svc::type_char`).
- Context menu: the `ContextMenuArea` is `enabled: false` and opened by hand (`menu.show(pos)`) from a row's `pressed` callback (a right press), which also selects the clicked row first; the position is the row's own plus the header height, the row index times 24 px and the list's `content-y`, because the area has the origin of the header. An enabled area opens itself on any right press that reaches it (it sits above or below the rows), before the row is selected; `show` does not check `enabled`. Its popup is drawn inside the window (no `muda` feature), so the snapshot script can capture it (`FASTPROCMAN_PAGE=menu`).
- **Every shortcut lives in `Main.shortcuts`**, a `FocusScope` around the whole window, not in `ProcessesPage`: a page-level scope only sees keys while the focus is inside the page. Its `capture-key-pressed` answers Enter/Escape for the dialogs before any focused item sees them (and swallows the rest); its `key-pressed` handles Escape (clears the filter), Ctrl+F, Delete, Up/Down, PageUp/PageDown (`ProcessesPage.move-page`, clamped, page = visible height / 24 px - 1), Left/Right (collapse/expand the selected tree row), Alt+Enter (Properties), Menu/Shift+F10 and typing, for any focus owner. The filter box repeats the Up/Down/Page/Alt+Enter cases in its own `key-pressed`; it keeps Left/Right for its cursor, so those two work only after a row was clicked.
- Tree group rows (`ProcRow.group`) have no process: every action on a process (menu, Delete, Alt+Enter, Menu key, `Main.ask`) checks `selected-label != ""`, which Rust leaves empty there, not `selected-row >= 0`. Enter/Left/Right still expand and collapse them.
- **A row press must hand the keyboard back to `Main.shortcuts`** (`focus-list` → `shortcuts.focus()`). The old `StandardTableView` took the focus itself; our rows are plain `TouchArea`s, and without this the filter box (focused at start) would keep Delete and the Menu key after a click, and End/Kill by keyboard would silently stop working. Snapshots cannot catch it: test by hand (click a row, press Delete → Confirm opens). The table has no `FocusScope` of its own. The "Expand all" / "Collapse all" buttons do the same after their click, for the same reason.
- Focus traps found the hard way (Slint 1.18 `window.rs`): (1) a focused item that becomes invisible loses the focus altogether, and switching tabs hides the whole Processes page, so `changed page` moves the focus to `shortcuts`; (2) closing a popup menu gives the focus back to what had it before the menu opened, so a dialog that opens from a menu item cannot rely on its own `FocusScope` (that is why the dialogs have none); (3) a text field takes Escape and the Menu key itself (a `LineEdit`'s own `ContextMenuArea` is a parent of the text; the `SearchBox` has no such menu), so those two are handled in the filter box's `key` callback, which runs first.
- Typing: `Main.key-pressed` calls the Rust `type-char`, which rejects control characters, Slint's private-use key codes (U+F700 to U+F8FF) and a first space, and puts the text in the filter. The cursor position passed to `set-selection-offsets` is a UTF-8 **byte** offset, so Rust computes it. Up/Down go through `ProcessesPage.move-selection` to `select-row`.
- The window is asked to take focus once at startup (`unstable-winit-030`, `with_winit_window(|w| w.focus_window())`), and `ui.show()` + `slint::run_event_loop()` replace `ui.run()` for that.
- Look follows FastMoji (`../FastMoji/ui/main.slint`): the burger is the kit's `MenuButton` (`controls.slint`, a borderless 28 px button, Tab and Space/Enter work), at the right end of the Processes filter row (so it is absent on the Graphs tab; `Ctrl+,` works everywhere) and opens Settings directly, with no popup menu (a fixed size: `width: self.height` there stretches the whole row). Toggles are `Switch` (label left, switch right, two-way `checked <=>`), dialog cards have a 1 px `Palette.border` and radius 10 instead of a shadow, padding 18 and spacing 14 (Properties keeps its default padding: its value `min-height` estimate assumes 380 px of text width).
- Settings: About lives in its button row (About + Close); the About handler closes Settings first (`settings-open` is answered before `about-open` in `capture-key-pressed`, so Escape would otherwise miss About). `Settings` is an overlay without a `FocusScope`: `Main.shortcuts.capture-key-pressed` answers Escape (close) and Space (flip the switch) and swallows the rest; `dismiss` calls `shortcuts.focus()`. The CPU scope divides only at display time (`State::cpu_shown`); sorting keeps the raw value. Snapshot page: `settings`.
- `GraphCard` needs `min-width`, `preferred-width: 0` and `horizontal-stretch: 1` together: an equal stretch alone leaves the grid columns different by the contents' minimum widths.
- Properties values are read-only `TextInput`s with a `min-height` from the character count (7.5 px per character over 380 px, 18 px per line). It over-estimates a little on purpose: under-estimating makes rows overlap.
- An open Properties dialog is refreshed on every sample (`update_properties`): CPU, running time, state, threads, memory, disk and the rest. It follows `State.props`, the `(pid, start)` it was opened for, not the table selection, and shows "Exited" once the process is gone. Fixtures skip it (made-up PIDs), so the snapshot is static.
